# Technical Deep-Dive Template

## Structure

### 1. Why This Matters (1-2 paragraphs)
- The problem this solves at a high level
- Why it's harder than it looks
- Connect to reader's likely experience

### 2. How It Works — The Simple Version (2-3 paragraphs)
- Explain the concept in simple terms first
- Use an analogy if helpful
- This sets the baseline understanding

### 3. The Actual Implementation (5-10 sections)
- Go through the real code/architecture
- Each section covers one component
- Include actual code from the project
- Explain WHY decisions were made, not just WHAT

### 4. The Hard Parts (2-3 sections)
- Where did the team get stuck?
- What took multiple iterations?
- What's non-obvious about the implementation?

### 5. Performance & Trade-offs (1-2 paragraphs)
- Benchmarks or measurements
- Known limitations
- When NOT to use this approach

### 6. Looking Under the Hood (optional)
- Internal details for the truly curious
- Edge cases handled
- Security considerations

## Formatting Rules
- Use architecture diagrams extensively
- Include real code with inline comments
- Reference actual git commits or PRs where possible
- Bold technical terms on first use with definition

## Length: 2000-4000 words
