# Data Storyteller Skill

## Purpose
Transform raw data findings into compelling, audience-ready stories using structured frameworks.

## Core Principle
**One story = one insight.** The insight is the MIDDLE of the story, not the end.

---

## Step 1: Refine the Insight

Before any storytelling, distill the raw finding into a single actionable insight.

Answer these questions in order:
1. What is the single most important thing the data shows?
2. What can the audience DO about it?
3. Why should they care?
4. What happens if they act? What if they don't?

**Insight Statement Formula:**
> The data shows [finding], which means [so what], and we should [action] because [outcome].

If you cannot state the insight in one sentence, you have more than one insight. Pick one.

---

## Step 2: Profile the Audience (ARE Framework)

Analyze your audience across three dimensions:

| Dimension | Questions to Ask |
|-----------|-----------------|
| **Authority** | Decision power? Hierarchy position? Empowered to act? |
| **Reason** | Domain knowledge level? Data literacy? Metrics they care about? |
| **Emotion** | Pre-existing beliefs? What matters to THEM? Timing pressures? |

Output: Audience profile with recommended framing, complexity level, and delivery format.

---

## Step 3: Outline the Story (7-Part Structure)

Build the narrative using this exact structure:

1. **SETTING** — Status quo before disruption (1-2 sentences). What's normal?
2. **HOOK** — The anomaly, change, or question that breaks the status quo (1-2 sentences)
3. **BEATS** — 3-4 data points building tension, ordered from satisfying → unsatisfying → most dissatisfying. Tension must never decrease.
4. **INSIGHT** — The single key finding ("aha moment"). This is the MIDDLE of the story.
5. **OUTCOME** — What we want to happen. The future state.
6. **ACTIONS** — Specific, concrete steps the audience should take
7. **MEASURES** — How we track whether it worked

**Constraint:** ONE insight only. If you have multiple insights, you have multiple stories.

---

## Step 4: Storyboard

Translate the outline into a visual plan:

- **Low-tech first** — sketch on paper or wireframe before opening any tool
- One slide/section per beat minimum
- Progressive revelation — build suspense, never dump information
- Each slide should make the audience want to see the next one

---

## Step 5: Select Format

Choose delivery format based on communication type and audience:

| Format | Best For | Constraint |
|--------|----------|------------|
| **Slide Deck** | Live presentations (direct communication) | <50 words per slide |
| **Infographic** | Self-contained, audience reads independently | Must stand alone without presenter |
| **Report** | Detailed documentation, text-heavy | Lead with executive summary, appendix for detail |
| **Interactive** | User-driven exploration | Must anticipate questions |
| **Hybrid** | Multi-stakeholder distribution | Adapt format per stakeholder group |

**Direct vs Indirect:** Direct = you control pacing (presentation). Indirect = audience controls pacing (document, email).

---

## Process Rules

- Can return to any previous step, but must re-execute forward from that point
- Who comes first. Always. Before what, before how.
- Narratives are more memorable than charts alone
- Context makes data stick
- Never dump information — build progressively
- Format affects story shape — can't just break a document into slides

---

## Decision: When to Use Story vs Chart

Stories help when insights are:
- Unpleasant
- Disruptive
- Unexpected
- Complicated
- Risky
- Costly

If the insight is straightforward and positive, a single chart or number may suffice.
